# Architecture decision records (ADRs)

An ADR captures **one** decision: the context, the options considered, what we chose, and what it
costs us. They're short on purpose. When a decision changes, add a new ADR that supersedes the old
one rather than editing history; the "why we used to do X" is often the most useful part later.

Format: Context → Options → Decision → Consequences (good and bad) → Revisit when.
